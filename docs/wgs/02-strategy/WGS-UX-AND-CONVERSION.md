# WGS UX and Conversion

## Core scenario

Someone hears about the business, searches for it, lands on the site, and quickly
decides whether it feels credible, relevant, professional, and worth contacting.
WGS designs the route from attention to informed action.

## Working sequence

1. Define audience groups by intent, not vague demographics.
2. Name the decision each group needs to make.
3. Map entry, questions, proof, objections, action, and recovery path.
4. Build the information architecture around those decisions.
5. Make one dominant action per section.
6. Test the sequence with realistic content on mobile and desktop.

## Conversion standard

- Explain the offer before asking for commitment.
- Put relevant proof near the claim it supports.
- Make links and buttons visibly actionable without hover.
- Distinguish primary and secondary actions.
- Keep forms proportionate to the value and qualification need.
- Treat accessibility, speed, and error recovery as conversion infrastructure.
- Never invent urgency, scarcity, testimonials, or results.

## Journey notation

Use concise flows such as `source → context → proof → decision → action`.
Record alternate routes for press, partners, buyers, returning users, and people
who are not ready to enquire.

## Validation

Test comprehension, task completion, keyboard access, focus, form behaviour,
responsive hierarchy, page speed, analytics events, and the honesty of claims.
