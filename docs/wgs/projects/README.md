# WGS Project Knowledge

For a serious project, create `docs/wgs/projects/<project-slug>/` with:

```text
00-brief.md
01-research.md
02-strategy.md
03-creative-direction.md
04-previs.md
05-design-spec.md
06-motion-spec.md
07-content-status.md
08-dailies.md
09-qa.md
10-results.md
```

Not every small project needs every document. Combine stages only when the
decision trail remains clear. Use `_templates/` and mark facts, approval, owners,
dates, unknowns, and source links. Never copy a previous project's decisions as
truth for a new client.
