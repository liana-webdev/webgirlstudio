# WGS Design Rules

## Hierarchy and composition

- Give each section a clear job and one dominant next step.
- Use scale, spacing, contrast, alignment, and sequence before decoration.
- Keep line length and type size readable; tiny labels cannot carry essential meaning.
- Use asymmetry deliberately while preserving scanning and content order.
- Show actual interface proof before extended explanation.
- Use one distinctive idea per section plus, at most, one supporting detail.

## Web-native art direction

Design real navigation, buttons, forms, galleries, accordions, case studies, and
responsive states. Avoid poster layouts with controls added afterward, fake
dashboards, meaningless 3D, excessive glow, and hover-only discovery.

## Mobile

Design mobile hierarchy intentionally. Recompose imagery, type, spacing, actions,
and interaction rather than shrinking desktop. Test at narrow widths, landscape,
zoom, coarse pointer, and reduced motion.

## Content and proof

Use realistic copy lengths and labelled project status. Never invent outcomes,
testimonials, interfaces, or urgency. Prefer screenshots and live links to claims.
