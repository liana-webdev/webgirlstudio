# WGS Case Study Standard

## Public structure

1. Hero: project, category, truthful status, concise description, primary live or interactive action.
2. Challenge: business reality, visible request, and diagnosis condensed.
3. System: journeys, information architecture, insight, and decisions.
4. Experience: the largest visual section with desktop, mobile, interaction, and responsive proof.
5. Evidence: real outcomes for clients; technical/functional evidence for studies.
6. Optional deep dives: UX decisions, responsive considerations, and strategy notes.
7. Relevant final action.

## Truth taxonomy

- Client work / founder-built / commissioned
- Live / launched / archived
- Independent study / fictional concept
- Interactive site / complete interface demonstration
- Draft / hidden / not approved for public listing

Do not call finished interactive work a prototype in public. Do not convert a
validation plan into completed evidence. Use only attributable metrics and
approved testimonials.

## Publish gate

Require final media, working primary links, mobile proof, truthful disclosure,
complete metadata, accessibility/functional QA, and a reason the work deserves a
place in the portfolio. Portfolio size is not a reason.
